1. Architecture Overview

PictureWall is a Node.js and Express application designed to serve as an interactive event picture marquee gallery and winner wheel.

Key Application Features & Storage Mechanics:
  • Backend Framework: Express.js server running in Node.js (default port: 3000).
  • Upload Handling: Multer handles multi-part image uploads up to 10MB per file.
  • Directory Hierarchy: Photos are saved on disk at Events/{eventId}/{userEmail}/{timestamp-filename}.
  • User Metadata: User display names are mapped in Events/{eventId}/users.json.
  • Authentication: Google Identity Services (OAuth 2.0 JWTs verified on frontend & parsed securely).

2. FTP / SFTP Deployment Steps

Follow these steps to transfer PictureWall to your remote Linux or hosting server using FileZilla, Cyberduck, or SFTP.

1

Prepare Local Files for Upload

Ensure you upload only source files and exclude local development dependencies and artifacts.

📁 picturewall/ (Root Directory)
├── 📁 css/
│ └── styles.css
├── 📁 js/
│ ├── auth.js
│ ├── event.js
│ ├── nav.js
│ ├── share.js
│ ├── utils.js
│ ├── wall.js
│ └── wheel.js
├── 📄 event.html
├── 📄 share.html
├── 📄 wall.html
├── 📄 wheel.html
├── 📄 setup.html
├── 📄 server.js
├── 📄 package.json
└── 📄 pnpm-lock.yaml (or package-lock.json)

🚫 DO NOT UPLOAD: node_modules/, .git/, or local temporary uploads in Events/.
2

Connect to Remote Server via FTP/SFTP

Open your FTP client (e.g. FileZilla, Cyberduck, or Command Line SFTP):

  • Protocol: SFTP (SSH File Transfer Protocol - Recommended) or FTP
  • Host: your-server-domain.com or Server IP
  • Port: 22 (for SFTP) or 21 (for FTP)
  • Remote Target Directory: /var/www/picturewall or /home/username/apps/picturewall
3

Transfer Files

Drag and drop all project files into your target web server application directory.

3. Server Directory & File Permission Setup (chmod)

Because PictureWall dynamically creates subfolders under Events/{eventId}/{userEmail}/ when admins create events or users upload photos, correct folder write permissions are mandatory!

Directory / Path Required Permission chmod Command Description
Events/ Required 775 or 777 chmod 775 Events or chmod 777 Events Allows Node.js web server process to create subdirectories and write images & users.json.
Project Root Directory 755 chmod 755 /var/www/picturewall Standard executable directory permission for web server access.
Source Files (*.html, *.js, *.css) 644 find . -type f -exec chmod 644 {} + Read permission for static files.
⚠️ Crucial Upload Permission Troubleshooting:
If image uploads fail with EACCES: permission denied, mkdir '.../Events/...', execute the following commands in SSH terminal: 
# Create the Events directory if it doesn't exist
mkdir -p Events

# Set write access permissions
chmod -R 775 Events

# Alternatively, set ownership to your Node process user (e.g., www-data or node)
sudo chown -R www-data:www-data Events

4. Node.js Environment & Process Manager Setup

Once files are uploaded via FTP, connect to your server via SSH terminal to install dependencies and run the server using PM2 or systemd.

1

Install Production Dependencies

Run npm or pnpm inside the application directory:

cd /var/www/picturewall
npm install --production
# OR if using pnpm:
pnpm install --prod
2

Start Application with PM2 Process Manager

PM2 ensures your Node.js application stays online continuously and automatically restarts after crashes or server reboots.

# Install PM2 globally if not installed
sudo npm install -g pm2

# Start server with Environment Variables
PORT=3000 ADMIN_EMAIL="your-admin@gmail.com" GOOGLE_CLIENT_ID="your-google-client-id.apps.googleusercontent.com" pm2 start server.js --name "picturewall"

# Save PM2 state for system startup reboot persistence
pm2 save
pm2 startup

5. Google Sign-In & Google Cloud Console Setup

PictureWall utilizes Google Identity Services (GSI) for user authentication and admin authorization. Follow these steps to generate your OAuth Client ID.

1

Create or Select a Google Cloud Project

  1. Navigate to Google Cloud Console.
  2. Click the project dropdown in the top bar and select New Project.
  3. Enter Project Name: PictureWall App and click Create.
2

Configure OAuth Consent Screen

  1. In the left sidebar, go to APIs & Services > OAuth consent screen.
  2. Choose User Type: External (available to any user with a Google account) or Internal (GSuite/Workspace).
  3. Fill out App Information:
    • App name: PictureWall
    • User support email: Select your email.
    • Developer contact information: Enter your email.
  4. Scopes: Add default scopes: .../auth/userinfo.email, .../auth/userinfo.profile, openid.
  5. Save and continue through to the dashboard.
3

Create OAuth 2.0 Web Client Credentials

  1. Go to APIs & Services > Credentials.
  2. Click + CREATE CREDENTIALS > OAuth client ID.
  3. Set Application type to Web application.
  4. Set Name: PictureWall Web Client.
  5. Authorized JavaScript origins: Add your domain(s) exact protocol, host, and port:
    • https://yourdomain.com
    • http://localhost:3000 (for local testing)
  6. Authorized redirect URIs: (Optional for standard GSI popups, recommended to add domain root):
    • https://yourdomain.com
  7. Click CREATE and copy your new Client ID (e.g. 1234567890-abcdef.apps.googleusercontent.com).

6. Environment Variables & Admin Email Configuration

Configure environment variables when launching server process or in a .env file / system environment.

Variable Default Value Description
GOOGLE_CLIENT_ID "" (Empty) Your Google OAuth 2.0 Client ID from Google Cloud Console. Enables live Google OAuth login button.
ADMIN_EMAIL lloyd.miguel@gmail.com The authorized Google email address permitted to create and manage events.
PORT 3000 HTTP port for Express web server.

Create an startup script or PM2 ecosystem config: 
# Example: starting server with env inline
GOOGLE_CLIENT_ID="123456789-xyz.apps.googleusercontent.com" ADMIN_EMAIL="admin@yourdomain.com" PORT=3000 node server.js
